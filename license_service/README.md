# 闲鱼订单授权服务

此服务统一使用完整闲鱼订单号作为兑换码，每个订单最多绑定两台设备。授权记录来自卖家人工核验录入或配置商品范围内的发货订单同步；仅输入一个不存在于授权库的订单号不会获得授权。

## 当前实现

- SQLite 保存订单号和兑换码 HMAC 摘要、Fernet 加密的订单号、设备哈希和必要审计事件，不保存明文订单号或兑换码。
- 管理页面 `/admin` 支持创建订单授权、撤销/恢复、删除和重置设备。无需填写另一个兑换码，API 也拒绝与订单号不一致的码。管理 API 使用环境变量 Bearer token。
- API 修改订单号时同步更新兑换码、加密订单信息与设备关联；重复导入和同步修复已有摘要，保留撤销状态、到期时间和设备名额。
- 同一订单仅有一条授权记录；相同设备重复激活幂等，并发激活也最多允许两台设备。
- 桌面端用 Windows 当前用户 DPAPI 和本机标识保护授权缓存；首次激活必须通过 HTTPS 服务验证，后续按以下离线租约规则校验。
- 客户端会在同机授权后保存短期离线租约：默认 24 小时内不重复请求授权接口；授权站点临时不可达时最多离线 30 天。服务器撤销、过期或设备超限会在下一次在线校验时生效；离线租约只用于容忍临时网络故障。
- 正式部署通过 `XIANYU_ITEM_IDS` 限定下载器商品 ID，只读同步后台的 `pending_ship`、`paid`、`shipped`、`completed` 订单，不依赖可能为空的发货内容。待付款、取消、退款中、已退款或未知状态不新增授权；其他商品不导入。已有授权的撤销状态和到期时间仍由管理员控制，不会被同步恢复。

## 部署要求

生产环境必须使用受信任且 SAN 覆盖服务域名的 HTTPS 证书。客户端默认地址在 `license_client.py` 中，为 `https://license.uling19.com`，不能关闭证书校验。

1. 使用受支持的 Python 3 环境安装 `requirements.txt`。
2. 为 `LICENSE_ADMIN_TOKEN` 和 `LICENSE_CODE_PEPPER` 分别生成独立的高熵随机值（至少 32 字节），写入仅 root 可读的服务环境文件；不要提交真实值或放进客户端。
3. 将数据库目录设为仅服务账户可读写，并纳入加密备份。不要把 SQLite 数据库放在仓库目录。
4. 用 systemd 等进程管理器运行 Uvicorn，**只监听 `127.0.0.1`**；由已配置可信 TLS 证书的反向代理终止 HTTPS，并加请求体上限、连接/请求超时以及基于来源 IP 的速率限制。公网防火墙只开放需要的 HTTPS 端口；管理页建议再加来源 IP allowlist 或 VPN。
5. 验证 `/health`、管理端未认证拒绝、HTTPS 证书链、重启后 SQLite 数据保留，再把客户端 API 地址与实际证书主机名核对一致。

管理员可调用 `POST /admin/sync-orders` 触发一次幂等同步。返回来源、新增、修复和跳过数量，不返回订单号或发货内容。激活时未找到订单会尝试同步一次。

升级旧的随机兑换码数据时，先用 SQLite backup API 备份生产数据库，再在服务环境中调用 `app.repair_order_codes()`。迁移一次事务内校正全部记录，并保留设备绑定、撤销和有效期；若订单无法解密或校验不一致则整批回滚。重复运行会返回 `repaired: 0`。迁移后客户统一使用订单号兑换，旧随机码不再接受。

## 运维注意

- 发布授权版之前，必须先完成服务部署、HTTPS 验证和 x64/x86 客户端打包验证。当前代码不包含管理员秘密，也不会自动尝试 SSH 部署。
- 服务器管理 token 泄漏后应立即换新并重启服务；Pepper 泄漏需按密钥轮换计划重置现有码摘要（旧兑换码将失效）。
- 删除记录会删除该订单的设备绑定；“重置设备”会释放此订单的两个激活名额。操作前请核对订单。
- 桌面应用的本地逻辑始终可能被有意修改；在线设备额度是服务端约束，不是无法绕过的 DRM。不要存放敏感内容或以此替代付款/订单核实。
